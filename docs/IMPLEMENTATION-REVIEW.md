## A new intervention medium

The three-instrument Lab makes the project's epistemic rules playable. Its
X3D rings, vanes, gates and lights use standard scene geometry. Gate colors
encode actual local state; neutral gray is unexamined. Motion starts disabled
and remains explicitly illustrative. It does not encode agent throughput.

1. **Identity:** hash the exact saved shader fixture with Web Crypto, append
   one newline and compare with its saved digest. Self-rebinding restores
   consistency while adding no independent witness.
2. **Discrimination:** the Python shader guard actually executes on five
   authored fixtures during building. Compare its saved outcomes against
   independent expected answers, then substitute an always-accept checker or
   omit failing controls. The guard ceases to qualify.
3. **Reuse:** apply the selected Controls qualification to an explicitly
   synthetic ledger. The qualified guard digest is bound to each row; input
   binding, target identity and passing consumption are required. Renaming or
   retrying the same tuple does not increase the count.

The third instrument does not infer scientific independence from a different
domain label. A distinct input is a protocol distinction; a real external
consumer needs a separate execution and adoption witness. Fixture acceptance
does not establish shader compilation or full X3D validity.

The byte manifest covers the exact case catalog and instrument scene; the
catalog names its producer and actual guard source hashes. The browser refuses
drift. Current X3D/JSON exports carry the observation and those identities.
No file-export operation sends data to another service.

## Actual import proof

The portable Lab X3D was imported into Blender 5.2.4 with the pinned public
importer identified in `receipts/review-blender.json`. All three actual gate
meshes and three mechanism-ring meshes match their source centers within the
declared tolerance; the ring comparisons use actual imported vertices.

The resulting studio still uses authored lighting/material adjustments. Imported
text is hidden and its labels are explicitly re-authored for readability. This
is an import/placement and presentation result, not native X_ITE pixels, shader
execution, gate evaluation, material parity or a GPU benchmark.

## Reusable heuristics and integration hooks

| Learning | MathLab / STEM / Chess application | Gobbler / ML / IO application |
| --- | --- | --- |
| Exact input before result | Retain initial conditions/FEN/units and the particular position being evaluated. | Bind source, guard, consumer, tool and run identities. |
| Counterexample beside example | Pair a true pin with a nearby unpinned position; preserve a scientific invariant while changing one boundary condition. | An always-pass guard fails on known mutants; duplicate content under a new row ID remains a retry. |
| Independent facets | Distinguish legal movement, numerical error, scientific interpretation and visible geometry. | Separate structure, semantic checks, empirical success, external adoption and human judgment. |
| One conversion, one loss report | Record axis, units, precision, camera and material differences at export/import. | Rebind transformed artifacts; retain derivation rather than borrowing a previous format's digest. |
| Lifecycle is semantic | A stale arrow or plot can make a false explanation. | A late callback or duplicate admission can make a false flywheel return. |
| Save both controls and results | Cross-language parity needs independent known answers. | A broad green receipt cannot substitute for a discriminating instrument. |

Use `docs/INTEGRATION-ONTOLOGY.json` for the vocabulary and actual field hooks.
Its twelve-work-item register deliberately retains deferred native execution,
crash recovery, consumer evidence and scaling. It is not a deployed reasoner,
a formal Loom acceptance profile or a claim that those proposals are complete.
